# HUMHUM 本体启动就绪与自动恢复设计

状态：已选方案 A，等待规格确认

## 背景与证据

2026-08-09 更新本地应用后，macOS 已创建 `280 × 210` 的 `main` 窗口，进程也保持存活，但本体完全不可见。系统日志显示三个 WebKit 内容进程首次启动均出现 `WebProcess failed to launch` 和 `Invalid connection identifier`。重启后无需修改模型或渲染代码，本体即可正常出现，因此根因是 WebView 没有成功进入可渲染状态，而不是 3D 模型损坏或窗口位于屏幕外。

现有启动验收只观察进程和窗口是否存在，会把“透明空壳”误判成成功。与此同时，`main`、`settings`、`hub` 三个 WebView 会在应用启动时一起加载，而且每个窗口首帧都暂时按 `main` 路由渲染，放大了启动资源竞争与错误面。

## 目标

- 只有本体真正画出首帧后，才把启动判定为成功。
- 本体首帧超时后自动恢复一次，不让偶发 WebKit 启动失败直接变成永久透明空壳。
- `settings` 和 `hub` 从第一帧起渲染自己的内容，不短暂初始化本体逻辑。
- 失败恢复过程有日志和用户可理解的反馈。
- 第一阶段保持小改动；Hub/设置按需创建作为独立第二阶段，不与本次修复捆绑。

## 方案

### 1. 窗口路由在首帧前确定

`App` 在 Tauri 环境中直接使用当前窗口的同步 `label` 作为初始值，不再把所有窗口默认成 `main` 后依赖 `useEffect` 修正。

结果：

- `main` 首帧进入 `PetWindow`。
- `hub` 首帧进入 `HubWindow`。
- `settings` 首帧进入 `SettingsWindow`。
- 隐藏窗口不再触发 `PetWindow` 的 bootstrap 副作用。

浏览器预览继续默认进入 Hub，不改变现有开发体验。

### 2. 以“本体首帧”作为 ready 信号

`PetCanvas` 在 2D 兜底画布第一次完成绘制后触发一次性回调。`PetView` 收到回调后调用窄接口 `report_pet_ready`，由 Rust 侧记录本次进程的本体已就绪状态。

选择 2D 首帧作为门槛，而不是等待 3D 模型：2D 是本体的可靠兜底，能保证用户先看到角色；3D 资源可继续异步加载并在就绪后平滑替换。

ready 信号必须满足：

- 每个 `main` 页面生命周期最多上报一次。
- 只有真实完成绘制才上报，组件挂载或窗口创建不算成功。
- Hub、设置和浏览器预览不发送本体 ready。

### 3. 原生启动看门狗

Rust 在应用 setup 完成后启动一个只针对 `main` 的一次性看门狗：

1. 等待 8 秒。
2. 若已收到 `report_pet_ready`，结束看门狗。
3. 若未收到，记录结构化告警并对 `main` WebView 执行一次 reload，同时确保窗口处于显示状态。
4. 再等待 8 秒。
5. 若仍未 ready，停止自动重试，记录明确错误并发送系统通知，提示用户从菜单栏选择“显示本体”或重启 HUMHUM。

只自动 reload 一次，避免启动故障形成无限重载或 CPU 循环。看门狗不重启整个应用，也不修改用户配置和持久数据。

### 4. 用户反馈与日志

正常启动不增加提示。只有恢复发生时才提供信号：

- 第一次超时：日志记录 `pet-startup-timeout` 和 `reload-attempt=1`。
- reload 后恢复：日志记录恢复耗时，不打扰用户。
- 第二次超时：系统通知使用人话说明“本体没有成功显示，HUMHUM 仍在菜单栏运行”，并给出可执行的下一步。

不向用户展示 WebKit、XPC、PID 等内部术语。

## 第一阶段范围

本轮实现：

- 首帧前确定窗口路由。
- 2D 本体首帧 ready 上报。
- 单次 reload 看门狗。
- 最终失败日志与系统通知。
- 前端和 Rust 回归测试。

本轮不做：

- 动态创建/销毁 Hub 与设置窗口。
- 重写 Tauri 窗口管理架构。
- 自动重启整个 HUMHUM 进程。
- 改动 3D 模型、角色外观或本体交互动作。

第二阶段在第一阶段稳定后单独实施：把 Hub 和设置从静态窗口配置迁移成用户打开时才创建，关闭后隐藏或销毁，并单独测量内存收益。

## 测试与验收

自动测试：

- App 路由测试证明 `hub`/`settings` 首帧不会渲染 `PetWindow`。
- 首帧信号测试证明只在真实绘制后上报一次。
- Rust 看门狗状态测试覆盖：按时 ready、不 ready 触发一次 reload、reload 后 ready、二次超时停止重试。
- 运行仓库 `verify` 选择出的前端和 Rust 质量门禁。

本机验收：

- 正常冷启动时，8 秒内可看到并拖动本体。
- 模拟第一次 ready 缺失时，只 reload 一次，随后恢复显示。
- 模拟持续失败时，应用不无限重载，并出现可理解的系统通知。
- 启动时 Hub 和设置不应短暂执行本体 bootstrap。
- 本体显示后右键、单击、拖动和 Hub 入口行为无回归。

## 成功标准

“HUMHUM 已打开”必须同时满足：应用进程存活、`main` 窗口在屏幕内、前端已上报本体首帧 ready。缺少任何一项都不能对用户宣称启动成功。
